# Chord–Scale Tree — Perfecto feature spec

A browsing tool for the chord-scale relationship. The user picks a note, a chord built on it, then a scale that has that chord as its home (tonic) chord, then any chord inside that scale. That chord becomes a new starting point, and the chain continues as far as the user likes.

**Reference prototype:** `docs/prototypes/chord-scale-tree.html`. Open it in a browser. All theory logic lives in its `<script>` block above the line `let sev=false`. When this spec and the prototype disagree, this spec wins. The test values below were generated by running the prototype's own engine.

**Target:** Perfecto (SwiftUI + AudioKit, iOS first, iPad layout planned).

---

## 1. Build order

1. **Theory engine** as a pure Swift package (`ChordScaleTheory`), with no UI or audio imports. Unit-test it against section 4 before writing any UI.
2. **Navigation model**: the selection chain and the child-generation rules in section 3.
3. **UI**: phone drill-down first, iPad column view second (section 5).
4. **Audio and MIDI** hooked into Perfecto's existing AudioKit synth and CoreMIDI virtual port (section 6).

## 2. Theory engine

### 2.1 Pitch spelling

Notes are spelled with a **letter plus an accidental**, never as bare pitch classes. Spelling matters: B Locrian is `B C D E F G A`, and F♯ major includes `E♯`, not `F`.

```swift
struct NoteName: Hashable {
    let letter: Int      // 0...6 = C D E F G A B
    let accidental: Int  // -2...+2  (𝄫 ♭ ♮ ♯ 𝄪)
    var pitchClass: Int  // (natural[letter] + accidental) mod 12; natural = [0,2,4,5,7,9,11]
}
```

**Spelling rule.** To spell the note `interval` semitones above `root`, taking `letterStep` letters up:

```
letter     = (root.letter + letterStep) mod 7
target     = (root.pitchClass + interval) mod 12
accidental = (target - natural[letter]) mod 12, then mapped into -6...+5   (if > 6, subtract 12)
```

- **Scales:** degree *i* uses `letterStep = i`, so each of the seven letters is used once.
- **Chords:** chord tone *i* uses `letterStep = 2i`, which gives stacked thirds.

**Picker spellings.** The 12 root notes are offered as: C, D♭, D, E♭, E, F, F♯, G, A♭, A, B♭, B.

**Normalising a new root.** When a chord's root becomes the root of a new scale, a root with a **double** accidental is respelled to its picker spelling above. Single accidentals such as F♭ and E♯ are kept as they are.

### 2.2 Scales: three families, 21 modes

Each family's interval pattern, measured from its first note:

| Family | Intervals |
|---|---|
| Major | 0 2 4 5 7 9 11 |
| Harmonic minor | 0 2 3 5 7 8 11 |
| Melodic minor | 0 2 3 5 7 9 11 |

Mode *k* (1–7) is the family rotated to start on degree *k*, then re-measured from the new first note. The display names, in order:

- **Major:** Ionian (major), Dorian, Phrygian, Lydian, Mixolydian, Aeolian (natural minor), Locrian
- **Harmonic minor:** Harmonic minor, Locrian ♮6, Ionian ♯5, Dorian ♯4, Phrygian dominant, Lydian ♯2, Ultralocrian
- **Melodic minor:** Melodic minor, Dorian ♭2, Lydian augmented, Lydian dominant, Mixolydian ♭6, Locrian ♮2, Altered

Keep families and mode numbers as data, not hard-coded names. That way, adding harmonic major or other scales later is a one-line change.

### 2.3 Chord qualities

| id | Intervals | Symbol | Name | Colour group |
|---|---|---|---|---|
| maj | 0 4 7 | *(none)* | Major triad | major |
| min | 0 3 7 | m | Minor triad | minor |
| dim | 0 3 6 | ° | Diminished triad | diminished |
| aug | 0 4 8 | + | Augmented triad | augmented |
| maj7 | 0 4 7 11 | maj7 | Major seventh | major |
| dom7 | 0 4 7 10 | 7 | Dominant seventh | major |
| m7 | 0 3 7 10 | m7 | Minor seventh | minor |
| mM7 | 0 3 7 11 | m(maj7) | Minor-major seventh | minor |
| hd7 | 0 3 6 10 | ø7 | Half-diminished seventh | diminished |
| d7 | 0 3 6 9 | °7 | Diminished seventh | diminished |
| aM7 | 0 4 8 11 | +maj7 | Augmented major seventh | augmented |
| a7 | 0 4 8 10 | +7 | Augmented seventh | augmented |

**The chord on scale degree *d*** is made by taking scale degrees *d*, *d*+2, *d*+4 (and *d*+6 for sevenths, wrapping mod 7). Measure each from degree *d* mod 12, then look up the resulting interval set in the table.

**The home chord of a mode** is its chord on degree 1.

**Hosts of a chord quality** are all modes whose home chord equals that quality. Only triads are compared with triads, and sevenths with sevenths.

### 2.4 Roman numerals

For a chord on degree *d* of a mode:

- **Numeral:** I–VII, lower-cased when the quality is in the minor or diminished colour group.
- **Prefix:** compare the mode's interval at *d* with the major scale's interval at *d*. A difference of −1 gives ♭, −2 gives 𝄫, +1 gives ♯, and +2 gives 𝄪.
- **Suffix by quality:** maj and min get nothing; dim → `°`, aug → `+`, maj7 → `maj7`, dom7 → `7`, m7 → `7`, mM7 → `(maj7)`, hd7 → `ø7`, d7 → `°7`, aM7 → `+maj7`, a7 → `+7`.

**Known simplification.** The Altered mode's home seventh chord stacks to `ø7` (G A♭ B♭ C♭ → G B♭ D♭ F). Jazz usage calls this chord "7alt", reading B♭ as ♯9 and C♭ as the major 3rd. Keep the stacked-thirds result for consistency, and leave room for a display-name override per mode later.

## 3. Navigation model

The state is `chain: [Node]`, an ordered list of selections, together with the `chordSize` setting (`.triads` or `.sevenths`).

```swift
enum Node {
    case note(NoteName)
    case chord(root: NoteName, quality: Quality, context: InScale?)   // context = (scale, degree, roman) when picked inside a scale
    case scale(root: NoteName, mode: Mode)
}
```

**Children of each node type:**

| Selected | Children shown next |
|---|---|
| `.note(r)` | All qualities of the current chord size, on root *r* (4 triads or 8 sevenths) |
| `.chord(r, q)` | One `.scale(normalised r, m)` for each host mode *m* of *q*, grouped by family |
| `.scale(r, m)` | The 7 diatonic chords of *m* from root *r*, each carrying its degree and Roman numeral |

After a chord picked inside a scale, the pattern continues: chord → scales → chords → and so on.

**Rules:**

- Selecting an item in level *i* **truncates** the chain after *i*, then appends the new selection.
- A chord with **no hosts** (`+7`, for example) can still be selected and auditioned, but it produces no next level. Show it with a distinct "no home scale" style, which the prototype draws as a dashed border.
- **Switching chord size** rebuilds the chain level by level, keeping each level that still has a match. Scales are matched by family and mode number. In-scale chords are matched by root spelling. Chords on a note are matched by colour group. Stop at the first level that has no match.
- **Opening state:** C → C (major) → C Ionian, so the first screen already shows a working example.

### 4.5 Property tests

- For every mode and every root, each scale degree uses a distinct letter.
- For every mode and every degree, the chord's root equals that degree's spelled scale note.
- **Round trip:** for every diatonic chord produced by a scale, that same scale (with its normalised root) appears among the chord's hosts whenever the chord sits on degree 1. More generally, the mode starting on degree *d* is always among the chord's hosts. This is the property the whole tool rests on.

## 5. UI

### 5.1 iPhone: drill-down

- Use a `NavigationStack`, with one level of the chain per screen.
- Show the full path as a **horizontally scrolling breadcrumb** at the top, for example `C › C › C Ionian › Em › E Phrygian`. Tapping a crumb pops back to that level.
- Each row shows: a colour dot for the quality group (scales get a square marker), the label, an optional Roman numeral, and the spelled notes in a monospaced caption.
- Group scale lists into **Major / Harmonic minor / Melodic minor** sections.
- Put a **compact two-octave keyboard** at the top of each screen. It highlights the tones of the focused item, labels them by spelled name, and marks the root more strongly.
- **Gestures:** a short tap selects and pushes the next level. A press-and-hold auditions the item and previews it on the keyboard without navigating. This replaces the prototype's hover preview.
- Put the Triads / Sevenths toggle in the toolbar, applying the rebuild rule from section 3.

### 5.2 iPad and wide layouts

- Use horizontal columns as in the prototype: one column per level, with curved connectors from the selected item to each of its children. The connector to the selected child is emphasised.
- Auto-scroll to the newest column whenever a level is added.
- Show the keyboard and readout in a header above the columns.

## 6. Audio and MIDI

- **Route sound through Perfecto's existing AudioKit synth.** Do not port the prototype's Web Audio code.
- **Chords:** play all tones together with a light strum of about 25 ms between notes, sustaining for about 1.6 s.
- **Scales:** play ascending, with the octave added at the top, about 170 ms per note.
- **Voicing:** place the root in octave 3 (C3 = MIDI 48). Stack the other tones upward by their intervals; do not fold them into a single octave.
- **Optional:** send the same notes out of the CoreMIDI virtual port, so the tree can drive external gear.
- Provide a sound on/off toggle. Selecting an item plays it while sound is on, and the readout's Play button always plays.

---

## 7. Out of scope for v1

- Scales beyond the three families (whole-tone, diminished, harmonic major, pentatonics). The `+7` chord's empty host list is expected for now.
- Non-tertian chords (sus, quartal, clusters).
- Inversions and voicing choices.
- Saving or sharing paths.
